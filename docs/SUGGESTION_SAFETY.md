# Local suggestion safety

The release candidate filters a finite, locally authored set of whole lexical forms for explicit sexual/pornographic terms, strong profanity and slurs in English, French and German. The lists are original project policy text, not copied from a corpus or external moderation list. They are in SuggestionSafety.kt; all three apply across layouts. No network requests, telemetry, user-text logging or new data files are introduced.

NFC and Locale.ROOT lowercasing handle canonical accent variants and case; curly apostrophes normalize to straight apostrophes. Additional orthographies/inflections are explicitly listed. There is no substring matching, blanket accent stripping, fuzzy censorship or automatic morphological expansion. Ordinary medical/health forms (including sex, sexual, penis, vagina and pregnancy) remain available. Ambiguous words/names such as Dick/dick, con and bite are deliberately not blocked: their meanings vary with language/context. This finite policy does not promise perfect NSFW recognition; novel compounds, euphemisms, obfuscation, unlisted variants and contextual meanings remain limitations. Some listed terms can also have nonoffensive meanings or be names: for example cock (rooster), tits (birds), German Schwanz (tail) and French couilles (slang anatomy) are suppressed as outputs, while clinical anatomy terms remain available. Dick/dick is deliberately retained as a name/German homograph; bite and con are retained because ordinary meanings across supported languages make a context-free ban overbroad. These choices leave contextual sexual/offensive uses of those ambiguous forms possible.

The policy controls outputs, never user permission to write. Existing dictionary membership, verbatim commits/paste, undo, and learned storage are retained. A listed original word is never automatically sanitized into a different word, even when absent from the dictionary and even if the model prefers another word. No learned count, manual addition or undo creates an override. The personal dictionary help states this limitation. No existing rows are deleted or rewritten.

Completions/corrections filter both bundled and learned candidates before display ranking; followers filter before top-k truncation and after dialect conversion. Automatic correction retains unfiltered confidence competitors and refuses an unsafe winning target, so removing unsafe candidates cannot promote a weaker automatic replacement. The US/UK conversion target is checked too. Context scoring refuses an open correction when an unsafe confidence competitor is present; safe scoring keeps the original word as a baseline and abstains when it wins. Confusable alternatives are checked before scoring. Service display, activation and asynchronous commit also check safety/current editor state.

Consequences: some suggestion slots can be empty; automatic/context corrections near blocked vocabulary can abstain more often. No physical-device/model-execution quality equivalence is claimed. The optional model still only scores finite candidates; it never generates free-form text. Password/email/URI and incognito learning protections remain unchanged.

This is not an assertion of age-rating compliance or removal of all mature app content. Emoji, custom shortcuts and user-authored text are unchanged; source dictionaries still contain broad vocabulary. Store questionnaires must describe actual remaining functionality/content. No Data safety/provider-collection conclusion follows from this output filter.

## Validation of this patch

Release unit tests on Robolectric API33/36: 115 passed, zero failures/errors/skips. Release lint: zero errors, 30 warnings and 3 hints. All 152 Python checks pass with the configured Temurin21 runtime; the system-default JDK lacks libdl/librt entries required by three unchanged PEPK fixtures, so its initial full-suite run failed those fixtures. No PEPK implementation or pins were altered. Actionlint and diff whitespace checks pass.

A local JVM probe loaded the unchanged shipped dictionaries and follower tables through the release SpellEngine classes. Top-two results included: EN fuc → fun/fur; shi → she/ship; FR merd → mère/mer; DE schei → scheint/scheinen. Neutral contexts: FR secteur → qui/culturel; DE namens → ken. Health terms sex/sexual and French/German equivalents remain available; murder/mord also remain ordinary news vocabulary. An earlier probe caught fuckin/merdé gaps; explicit variants were added and the final source was retested. These targeted examples establish behavior, not a population-level accuracy or completeness claim.

Tests exercise real service typing/undo/stale activation/delayed-commit guards and deterministic injected model scores. No native model execution, emulator/physical-device test or new unsigned/signed AAB build was performed for this patch. The existing screenshots/assets and dictionary/provenance files remain unchanged. Independent review precedes normal merge and a new protected build.

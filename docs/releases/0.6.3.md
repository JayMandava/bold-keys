# Bold Keys 0.6.3

Better contextual suggestions, local learning and an optional QAT model, while keeping the existing keyboard layout and two-word suggestion strip.

## What's changed

- Rank partial-word suggestions using the preceding word. Widen bounded conversational and technical candidate coverage without changing the automatic-correction thresholds.
- Learn known-word preferences, accepted suggestions and useful adjacent word pairs locally. Keep storage bounded, and clear words/preferences/pairs together with **Clear all learning**. Removing a personal word also removes its learned pairs.
- Add **Gemma 3 270M QAT** as a third optional model. Existing compact/precise model IDs, defaults and saved choices are preserved. The QAT download is pinned to its publisher revision, size and SHA-256; catalogue-file imports verify that identity before replacement. No QAT quality or speed improvement is claimed.
- Make the entire installed-model selection row and label selectable, with one accessible radio action. Explain when a model is only an effective fallback; tapping it explicitly saves the choice. Download, Cancel and Delete remain separate controls.
- Preserve no-learning behavior for incognito and sensitive editors, keep password/email suggestions suppressed, and prevent Settings clears from being overwritten by pending or asynchronously loaded learning.

Also included since the last public GitHub release, v0.6.1:

- Target Android 16/API 36 while retaining Android 13 minimum and arm64 support.
- Add the privacy-policy link, clearer provider/network descriptions and accessible offline licences/credits.
- Respect editor privacy flags for learned words and emoji personalization. Improve individual keyboard/suggestion accessibility controls without adding editor-text announcements.
- Replace next-word corpus inputs with pinned Common Voice CC0 text, retain the existing spelling dictionaries and apply local suggestion-safety filtering.

Keyboard geometry and sizing are unchanged.

## Testing and limits

The final picker source passed 102 tests in each debug/release suite on API 33 and API 36 with JDK 21, plus both suites on JDK 17/API 33; all had zero failures/errors/skips. Both lint checks had zero errors. Automated tests include real Compose touch/semantics actions, model persistence/integrity and synthetic download-failure cases. Independent review found no unresolved blocker. Release checks are repeated on the final versioned source before production signing and publication.

Reported physical checks used the isolated debug review app on a CPH2467 running Android 17. Earlier checks covered nine targeted ranking cases, synthetic learning/clearing, typing/undo and privacy behavior. The user reported a successful actual QAT download, whose file hash was verified on the prior QAT build. On the final picker review build, label/details taps saved QAT, fallback use was explained without silently changing preferences, reopening retained the choice, cancelling the import picker and unavailable-row behavior passed, and a targeted contextual correction still worked. The user's review keyboard/model settings were preserved.

Live Download/Cancel/Delete, TalkBack and selection of absent Q4/Q8 models were not physically exercised on that final picker build; automated tests cover the corresponding row actions and semantics. Phone checks used a review APK, not the final production-signed release APK. Limited QAT smoke tests and successful download do not establish comparative model quality or performance. Cloud model download remained blocked and was not retried.
